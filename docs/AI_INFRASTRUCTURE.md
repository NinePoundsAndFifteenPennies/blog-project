# AI 基建文档

本文档定义博客项目接入 AI 能力时的基础架构、约束与开发范式。  
目标是先统一底层规则，确保后续功能可以稳定、可控、可审计地迭代。

## 1. 范围与原则

1. **本项目 AI 能力仅面向已注册且已登录用户开放**。未登录用户禁止调用任何 AI 接口。  
2. **所有 LLM API 必须使用国产大模型服务**，禁止接入境外模型 API。  
3. AI 功能必须遵循现有安全体系（JWT 认证、RBAC、审计日志、异常处理）。
4. AI 相关实现应保持“可替换模型、可追踪调用、可灰度发布”的工程能力。

## 2. 模型与供应商策略（国产）

> 以下信息为联网调研结果（2026-03-10），用于初始选型；实际生产以供应商最新文档为准。

- **阿里云百炼 / 通义千问**
  - 官方文档显示中国内地部署可用 `千问 Max / Plus / Flash / Coder`，并包含 `Qwen3.5` 系列能力。
  - 参考：https://help.aliyun.com/zh/model-studio/getting-started/models
- **DeepSeek API**
  - 官方文档当前显示 `deepseek-chat`、`deepseek-reasoner` 对应 `DeepSeek-V3.2` 能力。
  - 参考：https://api-docs.deepseek.com/zh-cn/quick_start/pricing

### 2.1 统一供应商抽象（必须）

后端新增 AI 能力时，必须通过统一抽象层调用，禁止业务代码直连供应商 SDK：

- `AiProvider`：定义统一请求/响应协议（文本生成、结构化输出、工具调用）。
- `AiProviderFactory`：根据配置选择 `QwenProvider`、`DeepSeekProvider` 等。
- `AiGatewayService`：统一处理重试、限流、超时、审计、降级与错误映射。

## 3. 认证与授权基线

1. 所有 AI 业务接口默认要求 `Authorization: Bearer <JWT>`。
2. 必须在服务层校验用户身份与账号状态（禁用用户不可调用）。
3. 管理员能力（如 Prompt 模板管理、模型路由策略）单独走 Admin 权限。
4. 后续如引入游客体验，必须走独立限频沙盒，不得复用正式 AI 通道。

## 4. 配置与密钥管理

1. API Key 仅允许保存在后端安全配置（环境变量/密钥服务），禁止写入前端。
2. 前端只能请求本项目后端 API，不得直接调用第三方模型接口。
3. 配置分层：
   - `ai.provider`（默认供应商）
   - `ai.model.default`（默认模型）
   - `ai.timeout-ms`、`ai.max-retries`
   - `ai.rate-limit.*`（按用户、按接口限频）

## 5. 调用链与可观测性

每次 AI 请求必须记录最小审计字段：

- `requestId`、`userId`、`featureCode`
- `provider`、`model`
- `promptTokens`、`completionTokens`、`estimatedCost`
- `latencyMs`、`status`、`errorCode`

要求：

1. 业务日志与审计日志分离。
2. 错误码统一映射，避免将供应商原始错误直接暴露给前端。
3. 对超时、429、5xx 实现指数退避重试与熔断降级。

## 6. 安全与内容治理

1. **输入治理**：对用户输入做长度限制、敏感词/违法内容预检、Prompt 注入特征拦截。
2. **输出治理**：对模型输出做二次过滤（违规、隐私泄露、危险指令）。
3. **数据最小化**：Prompt 中默认不传用户敏感字段（手机号、邮箱、Token、密码等）。
4. **隐私隔离**：不同用户上下文不得串用；会话缓存按用户维度隔离。

## 7. 成本与配额治理

1. 按用户、按天设置调用配额（请求次数 + token 总量双限额）。
2. 高成本模型（如推理模型）默认仅用于明确需要的场景。
3. 达到阈值后自动降级到低成本模型或返回稍后重试提示。
4. 每周输出 AI 成本报表，纳入运维巡检。

## 8. 开发范式（后续功能统一遵循）

1. **先定义契约再开发**：先定 DTO 与错误码，再实现服务逻辑。
2. **提示词模板化**：Prompt 使用版本化模板（含版本号、发布记录、回滚能力）。
3. **功能开关**：每个 AI 功能必须支持配置开关与灰度发布。
4. **可测试性**：Provider 层可 Mock，业务层可通过集成测试覆盖成功/失败/降级路径。
5. **向后兼容**：新增字段优先“可选”，避免破坏已有客户端。

## 9. 非功能性目标

- 可用性：AI 主链路月度可用性目标 ≥ 99.9%
- 时延：P95 响应时延按功能分层设定（同步功能优先 < 3s）
- 可维护性：单个 AI 功能支持独立开关、独立限频、独立观测指标

## 10. 里程碑约束

在任何 AI 功能上线前，必须先满足：

1. 用户鉴权与配额机制已接入；
2. 审计日志与成本统计已可用；
3. 内容安全过滤链路已启用；
4. 至少完成一个主供应商 + 一个备用供应商的联调。
